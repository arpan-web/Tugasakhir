BAB I PENDAHULUAN
Latar Belakang
Kesehatan merupakan salah satu kebutuhan yang berkaitan dengan aktivitas sehari-hari, termasuk kegiatan di lingkungan perguruan tinggi. Dalam penyelenggaraan pelayanan kesehatan, data pasien, hasil pemeriksaan, pemberian obat, dan laporan pelayanan perlu dicatat sebagai bagian dari kegiatan administrasi. Perkembangan teknologi informasi memungkinkan pencatatan tersebut dilakukan melalui sistem digital, seperti rekam medis elektronik (Electronic Medical Record/EMR), sistem pendaftaran, dan pengelolaan persediaan obat [1][2]. Sistem digital dapat digunakan untuk menyimpan dan mengelola data pelayanan dalam satu sistem sehingga informasi yang dibutuhkan dapat tersedia untuk mendukung kegiatan pelayanan kesehatan [1].
Politeknik Negeri Pontianak (POLNEP) menyediakan layanan kesehatan bagi sivitas akademika melalui Poliklinik POLNEP. Poliklinik tersebut berada di lingkungan kampus, tepatnya di samping Gedung UPA Bahasa atau Gedung Perpustakaan lama. Pelayanan yang diberikan ditujukan kepada mahasiswa, dosen, dan tenaga kependidikan yang membutuhkan pemeriksaan maupun penanganan kesehatan selama berada di lingkungan kampus.
Pelayanan di Poliklinik POLNEP melibatkan pasien, perawat, dan dokter. Proses pelayanan dimulai ketika pasien melakukan pendaftaran di loket. Setelah pendaftaran, perawat melakukan pemeriksaan awal berupa pengukuran suhu tubuh, tekanan darah, berat badan, dan tinggi badan. Data pemeriksaan awal kemudian digunakan dalam proses pemeriksaan oleh dokter untuk mencatat kondisi pasien, diagnosis, dan tindakan yang diberikan. Apabila pasien memerlukan obat, dokter membuat resep yang selanjutnya digunakan oleh perawat atau petugas untuk menyiapkan obat. Data kunjungan dan penggunaan obat kemudian direkap oleh admin sebagai bagian dari laporan pelayanan poliklinik.
Berdasarkan pengamatan awal di Poliklinik POLNEP, pencatatan pada beberapa proses pelayanan masih menggunakan buku dan formulir kertas. Pendaftaran pasien, hasil pemeriksaan, resep, dan data persediaan obat dicatat pada media tersebut. Penggunaan beberapa media pencatatan menyebabkan data pasien dan pelayanan tersimpan pada dokumen yang berbeda. Ketika data riwayat pasien diperlukan kembali, petugas perlu mencari catatan yang sesuai pada dokumen sebelumnya. Pencatatan stok obat juga dilakukan secara terpisah sehingga perubahan jumlah obat perlu diperbarui setiap terjadi penerimaan atau pengeluaran obat. Kondisi tersebut juga berpengaruh pada proses penyusunan laporan karena data dari berbagai catatan perlu dikumpulkan dan direkap kembali.
Kondisi pencatatan yang ditemukan di Poliklinik POLNEP juga menjadi pembahasan dalam beberapa penelitian mengenai pelayanan kesehatan yang masih menggunakan pencatatan berbasis kertas [3][4]. Penelitian tersebut membahas pengelolaan data rekam medis, persediaan obat, antrean pasien, serta kegiatan administrasi yang masih dilakukan secara manual [4][5]. Penelitian lainnya membahas penggunaan sistem informasi untuk mengelola data pelayanan yang sebelumnya dicatat melalui beberapa media secara terpisah [1][6]. Hal tersebut menjadi salah satu pertimbangan dalam perancangan sistem yang dapat mengelola data pelayanan Poliklinik POLNEP dalam satu sistem.
Berdasarkan kondisi tersebut, pada tugas akhir ini dirancang Sistem InformasiManajemen Poliklinik Berbasis Web untuk Poliklinik POLNEP. Sistem dirancang untuk menangani pendaftaran dan antrean pasien, pencatatan pemeriksaan dan rekam medis, pembuatan resep, pengelolaan persediaan obat, serta penyusunan laporan. Sistem juga menyediakan notifikasi ketika persediaan obat mencapai batas minimum dan dashboard yang menampilkan data kunjungan serta penggunaan obat dalam bentuk grafik. Antarmuka sistem dirancang responsif agar dapat digunakan melalui komputer maupun perangkat dengan ukuran layar yang berbeda. Seluruh fungsi tersebut ditempatkan dalam satu sistem sehingga data pelayanan Poliklinik POLNEP dapat dikelola berdasarkan kebutuhan masing-masing pengguna.
Rumusan Masalah
Berdasarkan latar belakang yang telah diuraikan, maka rumusan masalah dalam tugas akhir ini adalah:
Bagaimana merancang sistem yang dapat mengotomatisasi proses pendaftaran dan manajemen antrean pasien secara efektif? 
Bagaimana sistem dapat merekam dan mengelola rekam medis pasien (diagnosis, tindakan, dan resep) secara terstruktur serta mudah ditelusuri? 
Bagaimana mengimplementasikan mekanisme pengelolaan inventori obat yang meliputi pencatatan transaksi masuk dan keluar serta peringatan stok obat minimal? 
Batasan Masalah
Penelitian ini dibatasi agar fokus dan terukur :
Penelitian ini dilakukan pada poliklinik di lingkungan Politeknik Negeri Pontianak (POLNEP) yang terletak di area kampus utama, tepatnya di sekitar  Unit Pelaksana Akademik (UPA) Bahasa sebagai salah satu fasilitas penunjang kegiatan akademik. Sistem ini dirancang khusus untuk memenuhi kebutuhan operasional pelayanan kesehatan internal bagi mahasiswa, dosen, dan tenaga kependidikan di lingkungan POLNEP.
Fitur yang dikembangkan dalam system ini meliputi: 
Manajemen Pendaftaran & Antrean: Proses pendaftaran pasien dan pengelolaan nomor antrean secara otomatis.
Manajemen Rekam Medis: Pencatatan riwayat kesehatan pasien (anamnesa, diagnosa, dan tindakan) oleh dokter secara digital.
Manajemen Inventori Obat: Pengelolaan stok obat yang mencakup pencatatan obat masuk, obat keluar, serta fitur notifikasi peringatan jika stok mencapai ambang batas minimal.
Dashboard Analitik: Visualisasi data kunjungan pasien dan penggunaan obat dalam bentuk grafik real-time untuk memudahkan pemantauan oleh pihak manajemen poliklinik.
Akses Multi-User: Sistem menyediakan hak akses yang berbeda untuk Admin dan Dokter sesuai dengan fungsinya masing-masing.
Data yang dikelola dalam sistem ini terbatas pada:
Data identitas sivitas akademika POLNEP (Mahasiswa dan Staf).
Data rekam medis pasien yang mencakup keluhan, hasil pemeriksaan fisik dasar, diagnosa, dan catatan resep.
Data master obat (nama obat, jenis, satuan, dan jumlah stok).
Data laporan kunjungan harian dan bulanan poliklinik.
Sistem ini dibangun dengan menggunakan teknologi sebagai berikut:
Bahasa Pemrograman:PHP.
Framework: Laravel.
Database:MySQL sebagai penyimpanan data relasional.
Frontend: HTML, CSS, JavaScript, dan Bootstrap (untuk memastikan tampilan yang mobile responsive).
Tujuan Tugas Akhir
Mengimplementasikan fitur pendaftaran pasien dan manajemen antrean secara otomatis dan efektif. 
Mengembangkan modul rekam medis yang mampu mencatat diagnosis, tindakan, dan resep secara terstruktur serta mudah ditelusuri. 
Mengimplementasikan sistem pengelolaan inventori obat yang mencakup pencatatan transaksi masuk dan keluar. 
Mengembangkan sistem yang mampu menyajikan informasi dalam bentuk dashboard analitik berbasis grafik real-time untuk mendukung proses monitoring dan pengambilan keputusan. 
Mengimplementasikan fitur notifikasi otomatis untuk memberikan informasi terkait kondisi tertentu seperti stok obat menipis dan status antrean pasien.
Manfaat Tugas Akhir
Tugas akhir ini diharapkan memberikan manfaat bagi berbagai pihak, antara lain:
Bagi Poliklinik POLNEP: memudahkan proses pendaftaran pasien, meningkatkan keterlacakan rekam medis dan resep, serta mempermudah pengelolaan stok obat.
Bagi pasien dan sivitas akademika: memberikan pelayanan yang lebih cepat, penyimpanan rekam medis yang rapi, serta memudahkan proses tindak lanjut.
Bagi penulis/mahasiswa: menambah pengalaman praktis dalam pengembangan sistem informasi kesehatan.
Metodologi Pelaksanaan Tugas Akhir
Metodologi pelaksanaan tugas akhir ini menggunakan metode Software Development dengan pendekatan System Development Life Cycle(SDLC) model Waterfall. Metode Waterfall ini dipilih karena meiliki tahapan yang terstruktur dan sistematis, sehingga sesuai dengan pengembangan sistem informasi dengan kebutuhan yang sudah jelas dan stabil.
Tahapan penelitian tugas akhir ini mengikuti metode Waterfall yang terdiri dari lima fase utama yaitu :
Analisis Kebutuhan (Requirement Analysist)
Pada tahap ini dilakukan identifikasi dari kebutuhan sistem melalui wawancara dan observasi di poliklinik POLNEP untuk memahami proses sistem yang sedang berjalan, permasalahan yang dihadapi, serta kebutuhan fungsional dan non-fungsional sistem yang kelak akan dibangun.
Perancangan Sistem (System Design)
Tahap ini meliputi perancangan arsitektur sistem, pembuatan entity relationship diagram (ERD), serta  perancangan antarmuka  pengguna (User Interface)
Implementasi (Implementation / Coding) 
Pada tahap ini akan melakukan pengembangan sistem menggunakan bahasa pemograman PHP dengan framework Laravel dan basis data MySQL. Sesuai dengan hasil perancangan yang telah dibuat.
Pengujian (Testing)
Tahap ini melakukan sebuah pengujian fungsionalitas sistem menggunakan metode Blackbox Testing untuk memastikan setiap fitur berjalan sesuai dengan kebutuhan, serta pengujian kepuasan pengguna (User Acceptance Testing).
Dokumentasi
Tahap akhir ini dapat meliputi penyusunan dokumentasi sistem berupa user manual, panduan penggunaan, dan dokumentasi teknis untuk mendukung pemeliharaan dan pengembangan sistem di masa mendatang.
Detail lengkap mengenai metode pengumpulan data, alat dan teknologi yang akan digunakan, serta metode analisis data akan dijelaskan pada BAB III Metode Tugas Akhir

BAB IIDASAR TEORI
2.1 Tinjauan Pustaka
Ringkasan Penelitian Terdahulu
Penelitian pertama dilakukan oleh Rano Agustino dkk. (2022) dengan judul “Perancangan Sistem Informasi Manajemen Klinik Berbasis Web dengan Menggunakan Metode System Development Life Cycle”. Penelitian ini bertujuan untuk merancang sistem informasi manajemen klinik berbasis web guna membantu proses administrasi dan pengelolaan data klinik secara efisien. Metode yang digunakan adalah System Development Life Cycle(SDLC) dengan model Waterfall, di mana hasil penelitian menunjukkan bahwa sistem tersebut berhasil mempermudah pengelolaan data pasien, dokter, apotek, dan laporan klinik. Namun, sistem ini masih memiliki kekurangan, yaitu belum tersedianya fitur notifikasi otomatis dan tampilan antarmuka yang belum mobile-friendly.
Penelitian kedua dilakukan oleh Hadi Irwan Nasrullah (2023) yang berjudul “Perancangan Sistem Informasi Manajemen Pasien Berbasis Web Pada Klinik Pratama Hijau Putih 9”. Tujuan penelitian ini adalah membangun sistem informasi yang membantu proses pendaftaran dan pengelolaan data pasien di klinik tersebut menggunakan model Waterfall. Hasil penelitian menunjukkan bahwa sistem mampu mempercepat proses registrasi dan mengurangi kesalahan input data. Meski demikian, sistem ini memiliki batasan karena belum mencakup fitur antrean online serta belum mendukung akses optimal melalui perangkat seluler.
Penelitian ketiga dilakukan oleh Gani dkk. (2019) dengan judul “Rancang Bangun Sistem Informasi Pelayanan Pasien dan Pengelolaan Obat di Poliklinik Politeknik Negeri Padang Berbasis Web”. Penelitian ini bertujuan untuk mengatasi kendala pencatatan manual pada poliklinik kampus yang menyebabkan lambatnya proses pencarian data rekam medis dan ketidakteraturan stok obat. Serupa dengan penelitian sebelumnya, metode yang digunakan adalah Waterfall dengan teknologi PHP dan MySQL. Hasil penelitian menunjukkan bahwa sistem mampu mempercepat pendaftaran dan memberikan akurasi pemantauan stok obat, namun belum dilengkapi dengan fitur dashboard visualisasi grafik dan notifikasi otomatis untuk stok kritis.
Berdasarkan ketiga penelitian tersebut, dapat disimpulkan bahwa pengembangan sistem informasi manajemen poliklinik berbasis web efektif dalam meningkatkan efisiensi pelayanan. Namun, masih terdapat celah pengembangan berupa kebutuhan akan fitur notifikasi otomatis, visualisasi data yang lebih informatif melalui dashboard, serta optimasi tampilan yang responsif pada perangkat mobile. Oleh karena itu, penelitian ini hadir untuk mengembangkan sistem yang lebih terintegrasi dengan tambahan fitur notifikasi, dashboard analitik grafik real-time, dan tampilan mobile responsive guna memberikan kenyamanan lebih bagi pengguna.

2.2 Dasar Teori
Dasar teori berisi konsep, teori, atau prinsip-prinsip ilmiah yang mendukung tugas akhir. Bagian ini menjelaskan landasan teoritis yang digunakan untuk merancang sistem atau menjawab rumusan masalah. Contoh struktur dasar teori sebagai berikut: 
Konsep Dasar
1. Sistem Informasi
Sistem informasi merupakan suatu kesatuan yang terdiri dari berbagai komponen yang saling berkaitan, seperti manusia (brainware), perangkat keras (hardware), perangkat lunak (software), data, dan prosedur. Komponen-komponen tersebut bekerja sama untuk mengumpulkan, mengolah, menyimpan, dan menyajikan data menjadi informasi yang berguna. Informasi yang dihasilkan digunakan untuk mendukung pengambilan keputusan serta pengendalian dalam suatu organisasi. Dengan adanya sistem informasi, proses pengelolaan data dapat dilakukan secara lebih efektif, efisien, dan terstruktur [7].
2. Manajemen Poliklinik
Manajemen poliklinik merupakan proses pengelolaan seluruh kegiatan pelayanan kesehatan yang dilakukan di lingkungan poliklinik. Kegiatan ini meliputi pendaftaran pasien, pengelolaan rekam medis, pengaturan jadwal dokter, pelayanan pemeriksaan pasien, pemberian resep obat, pengelolaan stok obat, serta pembuatan laporan kegiatan klinik. Manajemen yang baik sangat penting untuk memastikan pelayanan kesehatan berjalan dengan lancar, meningkatkan kualitas pelayanan, serta mempermudah tenaga medis dalam menjalankan tugasnya [8].
3. Sistem Berbasis Web
Sistem berbasis web adalah sistem yang dapat diakses melalui browser dengan memanfaatkan jaringan internet atau intranet. Sistem ini tidak memerlukan instalasi khusus pada perangkat pengguna sehingga dapat digunakan secara fleksibel dari berbagai perangkat seperti komputer, laptop, tablet, maupun smartphone. Dengan sistem berbasis web, pengguna dapat mengakses informasi kapan saja dan di mana saja, sehingga sangat mendukung mobilitas dan efisiensi dalam penggunaan sistem [9].
4. Basis Data (Database)
Basis data merupakan kumpulan data yang tersusun secara sistematis dan terorganisir sehingga dapat dengan mudah diakses, dikelola, dan diperbarui. Data dalam basis data disimpan dalam bentuk tabel yang terdiri dari baris (record) dan kolom (field), serta memiliki kunci utama (primary key) sebagai identitas unik dan kunci tamu (foreign key) sebagai penghubung antar tabel. Dalam sistem informasi poliklinik, basis data digunakan untuk menyimpan berbagai informasi penting seperti data pasien, dokter, pendaftaran, diagnosa, resep, dan obat. Penggunaan basis data yang baik dapat meningkatkan keakuratan data, mempercepat proses pencarian, serta mengurangi terjadinya duplikasi data[6].
5. Entity Relationship Diagram(ERD)
(ERD) merupakan model yang digunakan untuk menggambarkan hubungan antar entitas dalam suatu sistem basis data. ERD terdiri dari entitas, atribut, dan relasi yang saling terhubung. Entitas merupakan objek utama dalam sistem seperti pasien, dokter, dan obat, sedangkan atribut merupakan informasi yang menjelaskan entitas tersebut. Relasi digunakan untuk menunjukkan hubungan antar entitas. Dengan adanya ERD, perancangan database menjadi lebih terstruktur dan sistematis, sehingga memudahkan dalam proses implementasi system[6].
6. Rekam Medis
Rekam medis adalah kumpulan data dan informasi yang berisi identitas pasien, riwayat penyakit, hasil pemeriksaan, diagnosa, tindakan medis, serta pengobatan yang diberikan kepada pasien. Rekam medis berfungsi sebagai dokumentasi resmi yang dapat digunakan sebagai acuan dalam proses pelayanan kesehatan selanjutnya. Selain itu, rekam medis juga membantu tenaga medis dalam memahami kondisi pasien secara menyeluruh serta mendukung pengambilan keputusan medis yang tepat.
7. User dan Hak Akses
User merupakan individu yang menggunakan sistem, seperti admin, dokter, dan perawat. Setiap user memiliki peran dan tanggung jawab yang berbeda dalam sistem. Oleh karena itu, diperlukan pengaturan hak akses (role-based access control) untuk membatasi akses pengguna terhadap fitur-fitur tertentu. Admin bertugas mengelola data dan laporan, dokter bertugas menginput diagnosa dan resep, sedangkan perawat bertugas melakukan pendaftaran pasien. Pengaturan hak akses ini bertujuan untuk menjaga keamanan data serta memastikan bahwa setiap pengguna hanya dapat mengakses fitur sesuai dengan tugas dan tanggung jawabnya.
Teori Pendukung
1. System Development Life Cycle (SDLC)
System Development Life Cycle (SDLC) merupakan metode pengembangan sistem yang digunakan untuk merancang dan membangun sistem informasi secara terstruktur dan sistematis. Metode ini terdiri dari beberapa tahapan, yaitu analisis kebutuhan, perancangan sistem (design), implementasi (coding), pengujian (testing), dan pemeliharaan (maintenance) [7]. Tahapan-tahapan tersebut dilakukan secara berurutan agar sistem yang dikembangkan sesuai dengan kebutuhan pengguna serta dapat meminimalkan kesalahan dalam proses pengembangan.
2. Manajemen Informasi dalam Pelayanan Kesehatan
Manajemen informasi dalam pelayanan kesehatan menekankan pentingnya pengelolaan data yang akurat, relevan, dan tepat waktu. Informasi yang dihasilkan harus memiliki tingkat keandalan yang tinggi, mudah diakses, serta aman dari kesalahan maupun kehilangan data [8]. Hal ini sangat penting karena tenaga medis seperti dokter dan perawat membutuhkan informasi yang cepat dan tepat dalam mengambil keputusan terkait diagnosis dan pengobatan pasien.
3. Keamanan Sistem Informasi
Keamanan sistem informasi merupakan aspek penting dalam pengembangan sistem, terutama dalam sistem yang mengelola data sensitif seperti data pasien. Sistem harus mampu menjaga kerahasiaan data (confidentiality), memastikan keutuhan data (integrity), serta menjamin ketersediaan data (availability) [9]. Oleh karena itu, diperlukan mekanisme keamanan seperti autentikasi pengguna, pengaturan hak akses, serta perlindungan terhadap serangan yang dapat mengancam sistem.
Teknologi yang Digunakan
1. PHP
PHP adalah bahasa pemrograman yang digunakan untuk menjalankan proses di sisi server. Bahasa ini berfungsi untuk mengelola logika aplikasi seperti memproses data dari pengguna, menghubungkan sistem dengan database, serta menghasilkan output berupa halaman web yang akan ditampilkan di browser. PHP bekerja sebelum halaman dikirim ke pengguna, sehingga pengguna hanya menerima hasil akhirnya saja [5].
2. Laravel
Laravel merupakan framework berbasis PHP yang digunakan untuk mempermudah proses pengembangan aplikasi web. Laravel menyediakan struktur kerja yang terorganisir dengan konsep Model-View-Controller(MVC), sehingga pemisahan antara logika program, tampilan, dan data menjadi lebih jelas. Selain itu, Laravel juga menyediakan berbagai fitur bawaan seperti routing, autentikasi, dan keamanan yang membantu developer membangun sistem dengan lebih cepat dan efisien[8][15].
3. HTML
HTML adalah bahasa markup yang digunakan untuk membangun struktur dasar dari sebuah halaman web. HTML berfungsi untuk menentukan elemen-elemen yang akan ditampilkan, seperti teks, gambar, tabel, dan form input. HTML tidak memiliki kemampuan untuk mengolah data atau membuat interaksi, melainkan hanya sebagai kerangka utama dalam pembuatan tampilan web[11].
4. CSS
CSS adalah bahasa yang digunakan untuk mengatur tampilan visual dari halaman web yang dibuat menggunakan HTML. CSS berfungsi untuk menentukan desain seperti warna, ukuran teks, jarak antar elemen, serta tata letak halaman. Dengan CSS, tampilan web menjadi lebih menarik, rapi, dan konsisten di berbagai perangkat[12].
5. JavaScript
JavaScript adalah bahasa pemrograman yang digunakan untuk memberikan interaksi pada halaman web di sisi client(browser). JavaScript memungkinkan halaman web menjadi dinamis, seperti melakukan validasi input, menampilkan notifikasi, serta mengubah tampilan secara langsung tanpa perlu memuat ulang halaman. Dengan JavaScript, pengalaman pengguna menjadi lebih interaktif dan responsive[13].
6. Bootstrap
Bootstrap merupakan frameworkCSS yang digunakan untuk mempercepat pembuatan tampilan antarmuka. Bootstrap menyediakan berbagai komponen siap pakai seperti tombol, form, tabel, dan navigasi, sehingga developer tidak perlu membuat desain dari awal. Selain itu, Bootstrap mendukung desain responsif yang memungkinkan tampilan web menyesuaikan berbagai ukuran layar perangkat[9].
7. MySQL
MySQL adalah sistem manajemen basis data yang digunakan untuk menyimpan dan mengelola data secara terstruktur. MySQL memungkinkan penyimpanan data dalam bentuk tabel yang saling berelasi, sehingga memudahkan dalam proses pengolahan dan pencarian data. Dalam sistem ini, MySQL digunakan untuk menyimpan data pasien, dokter, pendaftaran, diagnosa, resep, serta stok obat[10].
8. Laragon
Laragon merupakan software yang digunakan sebagai server lokal (localhost) dalam proses pengembangan aplikasi web. Software ini menyediakan layanan seperti Apache sebagai web server dan MySQL sebagai database server. Dengan menggunakan XAMPP atau Laragon, developer dapat menjalankan dan menguji sistem secara lokal sebelum dipublikasikan ke server online.
Hubungan dengan Tugas Akhir
Berdasarkan konsep dan teori pendukung yang telah dijelaskan, sistem informasi manajemen poliklinik yang diusulkan akan dikembangkan dengan menerapkan metode SDLC (System Development Life Cycle) agar proses pengembangan berjalan secara sistematis, mulai dari tahap analisis kebutuhan hingga pemeliharaan sistem.
Sistem ini dirancang untuk mendukung kegiatan operasional poliklinik, yang meliputi pendaftaran pasien, manajemen antrean, pengelolaan rekam medis (diagnosis, tindakan, dan resep), serta pengelolaan inventori obat. Selain itu, sistem juga dilengkapi dengan kontrol akses berbasis peran (admin dan dokter) guna menjaga keamanan dan keteraturan dalam penggunaan sistem.
Pemanfaatan teknologi berbasis web memungkinkan sistem dapat diakses secara fleksibel melalui berbagai perangkat, sehingga meningkatkan efisiensi pelayanan dan kemudahan dalam pengelolaan data. Dengan dukungan teknologi seperti PHP, Laravel, MySQL, serta antarmuka berbasis HTML, CSS, dan JavaScript, sistem diharapkan mampu memberikan solusi yang efektif, terintegrasi, dan sesuai dengan kebutuhan operasional poliklinik POLNEP.
BAB III PERANCANGAN SISTEM
3.1 Analisis Kebutuhan Sistem
Bagian ini menjelaskan kebutuhan sistem yang akan dibangun, baik kebutuhan fungsional maupun non-fungsional.
Kebutuhan Fungsional:
Fitur-fitur utama yang akan dimiliki sistem, sebagai berikut:
Manajemen Data Master: sistem harus mampu dalam mengelola data master (data obat, data dokter dan data poli)
Pendaftaran Pasien: sistem harus dapat menyediakan fitur untuk mendaftar pasien baru dan mencatat kunjungan pasien
Pencatatan Diagnosa dan Pengobatan: sistem harus dapat memungkinkan mencatat diagnosa dan resep obat untuk pasien 
Manajemen Stok Obat: sistem harus dapat mencatat setiap stok obat yang masuk dan keluar serta dapat memberikan peringatan atau pengingat jika stok obat hampir habis
Autentikasi Pengguna: sistem harus menyediakan fitur login pengguna dan logout untuk mengamankan akses data berdasarkan (admin, dokter)
Pembuatan Laporan: sistem harus dapat menghasilkan laporan -laporan rutin, seperti:
Laporan kunjungan pasien (harian, mingguan dan bulanan)
Laporan penggunaan obat 
Laporan diagnosa penyakit pasien
Kebutuhan Non-Fungsional:
(Usability/Interface)Sistem harus memiliki antarmuka yang sederhana, konsisten, dan mudah dipahami sehingga pengguna dapat mengoperasikan setiap fitur tanpa mengalami kesulitan.
(Reliability)Sistem harus mampu menjalankan setiap fungsi secara konsisten tanpa mengalami kesalahan yang dapat mengganggu proses pelayanan di Poliklinik POLNEP.
(Security)Data pasien dan transaksi obat harus terlindungi dalam sistem. Hanya pengguna yang terdaftar dan memiliki kredensial yang valid yang dapat mengakses sistem. Data sensitif, seperti diagnosis dokter dan rekam medis, harus disimpan dengan aman. 
(Performance)Sistem harus mampu memproses pencarian, penyimpanan, dan penampilan data pasien, rekam medis, serta stok obat dengan cepat agar pelayanan di poliklinik tidak mengalami keterlambatan.
(Safety)Sistem harus membantu meminimalkan kesalahan input data pasien melalui validasi data sebelum disimpan..
3.2 Arsitektur Sistem
Menjelaskan gambaran umum sistem secara keseluruhan, termasuk komponen-komponen utama dan hubungan antar komponen.
Diagram Arsitektur
Diagram arsitektur berikut menjadi gambaran struktur utama sistem, yang dimulai dari interaksi pengguna (admin dan dokter), antaramuka web (front-end), logika aplikasi (back-end), hingga dengan penyimpanan data (database server).
Penjelasan Komponen:
Berikut penjelasan fungsi dari setiap komponen utama yang ada di sistem :
a) Pengguna Sistem
Pengguna sistem merupakan pihak yang memiliki hak akses untuk menggunakan aplikasi melalui web browser. Sistem menyediakan dua jenis pengguna, yaitu:
1) Admin
Admin bertanggung jawab mengelola seluruh data yang terdapat pada sistem. Tugas admin meliputi:
Login ke sistem.
Mengelola data master (pasien, dokter, poli, dan obat).
Melakukan pendaftaran pasien.
Mengelola data stok obat.
Melihat serta mencetak laporan kunjungan pasien, diagnosa, dan penggunaan obat.
2) Dokter
Dokter bertugas memberikan pelayanan medis kepada pasien melalui sistem. Tugas dokter meliputi:
Login ke sistem.
Melakukan pemeriksaan pasien.
Menginput hasil diagnosa.
Menentukan tindakan medis.
Membuat resep obat sesuai hasil pemeriksaan.
b) Browser
Browser merupakan media yang digunakan oleh pengguna untuk mengakses aplikasi melalui jaringan internet atau intranet. Pada penelitian ini, sistem dapat dijalankan menggunakan browser seperti Google Chrome, Microsoft Edge, Mozilla Firefox, maupun browser modern lainnya.
c) Front-End (Blade + Bootstrap)
Front-end merupakan bagian sistem yang berfungsi sebagai antarmuka (user interface) yang digunakan pengguna untuk berinteraksi dengan aplikasi melalui web browser. Pada penelitian ini, front-end dikembangkan menggunakan Blade Template sebagaitemplate engine Laravel dan Bootstrap sebagai framework CSS sehingga tampilan sistem responsif, konsisten, dan mudah digunakan[8][9].
Fitur utama yang tersedia pada front-end meliputi:
Form login pengguna.
Form pendaftaran pasien.
Halaman pemeriksaan dokter.
Form resep obat.
Dashboard dan laporan harian.
Notifikasi stok obat minimum.
d) Back-End (Laravel Framework)
Back-end merupakan bagian sistem yang bertugas menangani seluruh proses bisnis, logika aplikasi, serta pengolahan data. Pada penelitian ini, back-end dikembangkan menggunakan Framework Laravel yang menerapkan arsitektur Model-View-Controller (MVC)[8][9].
Komponen utama pada back-end meliputi:
Route, menerima setiap permintaan (request) dari pengguna dan mengarahkannya ke controller yang sesuai.
Controller, mengelola logika aplikasi dan memproses data dari pengguna.
Authentication, menangani proses login, logout, serta pengaturan hak akses pengguna.
Business Logic, menjalankan proses bisnis seperti pendaftaran pasien, pemeriksaan, pengelolaan stok obat, dan pembuatan laporan.
Model (Eloquent ORM), menghubungkan aplikasi dengan database serta melakukan proses pengambilan, penyimpanan, pembaruan, dan penghapusan data.
e) Database Server (MySQL)
Database Server menggunakan MySQL sebagai sistem manajemen basis data relasional yang berfungsi menyimpan seluruh data master maupun data transaksi sistem secara terstruktur[10].
Data yang disimpan meliputi tabel USER, PASIEN, DOKTER, POLI, JADWAL_DOKTER, PENDAFTARAN, DIAGNOSA, RESEP, RESEP_DETAIL, OBAT, STOK_TRANSAKSI, NOTIFIKASI, dan CATATAN_HARIAN_OBAT.
Database MySQL memastikan seluruh data seperti pendaftaran pasien, hasil pemeriksaan, diagnosa, resep obat, transaksi stok, hingga laporan tersimpan secara aman, konsisten, dan dapat diakses oleh aplikasi melalui Model (Eloquent ORM).

Prinsip Desain
Desain antarmuka ini dibuat dengan memerhatikan prinsip usability, consistency, dan aesthetics, agar sistem dapat dengan mudah digunakan, tampak professional, dan nyaman bagi pengguna.
Usability
Antarmuka dirancang agar dengan mudah digunakan oleh semua peran pengguna, yaitu, admin, dokter, dan perawat. Navigasi dibuat sederhana melalui menu sidebar yang mudah diakses. Setiap pengguna hanya dapat melihat menu yang relevan dengan perannya (role-based-menu), sehingga tidak membingungkan. Sistem juga dilengkapi dengan validasi form untuk mencegah kesalahan input serta peran konfirmasi yang digunakan untuk tindakan penting seperti penghapusan data[14].
Consistency 
Tampilan sistem dijaga konsistensinya dalam warna, tata letak, dan gaya komponen. Warna biru digunakan sebagai warna utama dalam sistem karena mencerminkan profesionalisme dan ketenangan dalam konteks pelayanan kesehatan. Semua tombol , form, dan elemen tabel memiliki gaya dan ukuran yang seragam agar pengguna dapat dengan mudah mengenali fungsi setiap elemen[14].
Aesthetics
Antarmuka dirancang dengan tampilan yang bersih dan modern dengan menggunakan kombinasi warna lembut, ikon sederhana, dan ruang kosong yang cukup antar elemen. Font yang akan digunakan dalam sistem memiliki keterbacaan tinggi, serta desain elemen seperti tombol dan kartu (card) memiliki sudut yang membulat untuk kesan modern. Tata letak yang rapi membantu pengguna fokus pada informasi utama seperti data pasien, diagnosa serta laporan[14].
Dengan penerapan ketiga prinsip ini, antarmuka sistem menjadi lebih mudah digunakan, konsisten dan nyaman dilihat, sehingga, dapat mendukung efisiensi kerja admin, dokter, dan perawat dalam kegiatan operasional poliklinik.
3.5 Perancangan Algoritma atau Proses Bisnis (Opsional)
Flowchart atau Diagram Alir:
Flowchart berikut menampilkan alur proses utama dalam sistem :
Pasien datang ke poliklinik dan melakukan pendaftaran melalui perawat atau admin.
Sistem akan menyimpan data pasien dan membuat data pendaftaran (nomor pendaftaran dan antrian).
Perawat akan melakukan triase awal seperti pengukuran suhu, berat, dan tinggi badan.
Dokter akan memeriksa pasien dan memasukkan hasil diagnosa dan tindakan medis.
Jika diperlukan, dokter membuat resep obat yang kemudian akan diserahkan kepada perawat.
Perawat mengambil obat dari stok gudang dan memberikan obat kepada pasien.
Sistem otomatis mencatat transaksi stok obat serta sistem akan membuat catatan harian obat.
Admin dapat mencetak laporan harian yang berisi data pasien, diagnosa, dan penggunaan obat.
Flowchart ini menggambarkan keterhubungannya antaran aktor utama yaitu (Pasien, Perawat, Dokter, dan Admin) dengan proses di sistem, dimulai dari pendaftaran pasien sampai dibuatnya laporan harian.
Penjelasan Algoritma
Algoritma yang akan digunakan adalah logika data berbasis CRUD (Create, Read, Update, Delete) yang akan diimplementasikan dalam setiap modul utama, dengan penjelasan sebagai berikut :
Algoritma pendaftaran pasien 
Sistem akan memeriksa apakah pasien sudah terdaftar di database.
Jika  belum, sistem akan menambahkan data baru ke dalam tabel pasien.
Jika sudah ada, sistem hanya akan membuat data pendaftaran baru dengan nomor antrian dan nomor pendaftaran otomatis.
Algoritma Pemeriksaan dan Diagnosa Dokter
Setelah pasien telah selesai diperiksa, dokter akan memasukkan diagnosa dan tindakan ke sistem. Data akan disimpan di tabel diagnosa yang terhubung dengan pendaftaran dan dokter.
Algoritma Pembuatan Resep dan Manajemen Obat 
Dokter membuat resep, kemudian sistem akan menyimpan data resep dan detail obat ke dalam tabel resep dan resep_detail. Saat resep disimpan, sistem secara otomatis akan mengurangi stok obat, dan mencatat transaksi di tabel stok transaksi.
Algoritma Pembuatan Laporan Harian
Sistem akan melakukan rekap otomatis berdasarkan data Pendaftaran, diagnosa, resep dan stok_transaksi yang akan menjadi laporan harian dan dicetak oleh admin[7].

BAB IV HASIL DAN PEMBAHASAN
4.1 Gambaran Umum Sistem
Sistem Informasi Manajemen Poliklinik POLNEP merupakan aplikasi berbasis web yang dirancang untuk mengintegrasikan dan memusatkan seluruh alur pelayanan kesehatan di Poliklinik Politeknik Negeri Pontianak. Sistem ini dibangun dengan arsitektur Model-View-Controller (MVC) menggunakan framework Laravel 10, basis data relasional MySQL, serta antarmuka yang responsif.
Level Akses dan Hak Pengguna
Sistem membagi hak akses ke dalam 3 (tiga) peran pengguna (roles) untuk menjaga keamanan dan kejelasan wewenang operasional:
Administrator (admin): Bertanggung jawab mengelola data pengguna/staff, data master (Poli, Dokter, Perawat, Obat), serta memantau laporan kunjungan dan logistik obat secara menyeluruh.
Perawat (perawat): Bertanggung jawab melakukan pendaftaran pasien (mahasiswa/civitas akademika POLNEP maupun pasien umum), menginput pengukuran tanda-tanda vital (suhu tubuh, tinggi badan, berat badan), serta menerbitkan nomor antrian pendaftaran harian.
Dokter (dokter): Bertanggung jawab menerima antrian pasien sesuai poliklinik tujuan, menginput diagnosa hasil pemeriksaan medis, mencatat tindakan kesehatan, serta meresepkan obat secara langsung yang terhubung otomatis dengan stok apotek.
Alur Kerja Sistem (Workflow)
Alur operasional pelayanan poliklinik pada sistem berjalan secara berurutan dan terintegrasi:
Tahap Pendaftaran & Skrining Awal: Pasien mendatangi poliklinik. Perawat menginput data pendaftaran pasien, mengukur suhu/TB/BB, dan sistem secara otomatis menerbitkan Nomor Pendaftaran (contoh: REG-20260309-001) serta Nomor Antrian Harian.
Tahap Pemeriksaan Medis: Dokter melihat daftar antrian pasien berstatus baru. Dokter memanggil pasien, status berubah menjadi diproses. Dokter menginputkan diagnosa penyakit dan tindakan medis.
Tahap Penulisan Resep & Pemotongan Stok Atomik: Dokter memilih obat dan dosis. Sistem melakukan pencatatan resep (RSP-YYYYMMDD-XXXX) dan secara atomik mengurangi jumlah stok_tersedia pada master obat. Status pendaftaran diperbarui menjadi selesai.
Tahap Transaksi Logistik & Pelaporan: Petugas farmasi/admin dapat menginput mutasi stok obat (masuk/keluar) yang secara otomatis memperbarui tabel stok_transaksis dan catatan_harian_obats. Admin dapat mengunduh/melihat Laporan Kunjungan, Laporan Diagnosa, dan Laporan Stok Obat.
4.2 Implementasi Sistem
Sub-bab ini menguraikan bagaimana Sistem Informasi Manajemen Poliklinik POLNEP diimplementasikan secara teknis berdasarkan rancangan sistem yang telah dibuat pada BAB III. Implementasi mencakup lingkungan pengembangan, implementasi basis data, implementasi antarmuka (GUI), fitur-fitur utama beserta fungsinya, serta potongan kode program penting.
Lingkungan Implementasi Sistem
Sistem dibangun menggunakan spesifikasi perangkat lunak (software) dan teknologi sebagai berikut:
Framework Back-End & Front-End: Laravel 10 (PHP v8.1+) dengan Blade Templating Engine.
Database Management System (DBMS): MySQL Database Server.
Web Server & Environment: Laragon / Apache Web Server.
Styling & User Interface: Bootstrap CSS Framework / Modern Responsive UI.
Implementasi Basis Data
Implementasi basis data dilakukan melalui fasilitas Migration pada Laravel. Berdasarkan rancangan basis data pada BAB III, sistem memiliki 12 tabel utama yang saling berelasi:
users: Menyimpan kredensial dan hak akses pengguna (admin, dokter, perawat).
pasiens: Menyimpan identitas pasien (kategori Civitas POLNEP / Umum).
polis, dokters, perawats: Menyimpan data spesialisasi poli dan staff medis.
pendaftarans: Menyimpan data registrasi antrian, keluhan, dan vital sign.
diagnosas, reseps, resep_details: Menyimpan rekam medis dan rincian resep obat.
obats, stok_transaksis, catatan_harian_obats: Mengelola stok logistik obat dan mutasi fisik.
Implementasi (GUI) dan Penjelasan Fitur Utama
Halaman Login
Halaman login adalah halaman pertama yang muncul ketika pengguna membuka aplikasi.Halaman ini berfungsi untuk memastikan bahwa hanya pengguna yang terdaftar saja yang bisa masuk ke dalam sistem.Tampilannya dibuat simpel dan rapi, hanya berisi kolom untuk mengisi username dan password. Setelah pengguna menekan tombol login, sistem akan memeriksa apakah username dan password yang dimasukkan sudah sesuai dengan data yang tersimpan di sistem, serta mengecek apakah akun tersebut dalam keadaan aktif atau tidak.Jika username dan password benar serta akun aktif, pengguna akan langsung diarahkan ke halaman utama (dashboard) sesuai dengan perannya masing-masing.
Halaman Dashboard Utama 
Halaman dashboard adalah halaman pertama yang muncul setelah pengguna berhasil masuk ke dalam sistem. Halaman ini berfungsi sebagai pusat informasi yang memberikan gambaran umum tentang kondisi poliklinik secara langsung dan terkini.
Di bagian atas halaman, terdapat empat kotak ringkasan informasi penting, yaitu:
Pasien Hari Ini — menampilkan jumlah pasien yang datang berobat pada hari tersebut
Antrian Menunggu — menampilkan jumlah pasien yang sedang menunggu giliran untuk diperiksa
Stok Obat Kritis — menampilkan jumlah obat yang stoknya sudah hampir habis atau di bawah batas minimum
Total Kunjungan — menampilkan total keseluruhan kunjungan pasien
Jika ada obat yang stoknya hampir habis, sistem juga akan menampilkan pesan peringatan secara otomatis beserta daftar nama obat yang perlu segera diisi ulang.Di bagian bawah, terdapat dua bagian tambahan. Bagian pertama adalah daftar antrian hari ini yang memperlihatkan nomor antrian, nama pasien, serta status pemeriksaannya — apakah masih menunggu, sedang diperiksa, atau sudah selesai. Bagian kedua adalah informasi umum poliklinik, seperti jam operasional, lokasi, jumlah dokter dan perawat yang tersedia, serta total jenis obat yang ada.
3) Halaman Data Pasien
Halaman data pasien digunakan untuk mengelola seluruh data pasien yang terdaftar di poliklinik. Pada halaman ini ditampilkan daftar pasien dalam bentuk tabel yang memuat informasi seperti nomor rekam medis, nama lengkap, jenis kelamin, status pasien (apakah civitas POLNEP atau umum), serta nomor HP.Pada halaman ini, pengguna dapat melakukan beberapa tindakan, yaitu:
a) Tambah Pasien — menambahkan data pasien baru ke dalam sistem
b) Daftarkan Antrian — langsung mendaftarkan pasien ke antrian pemeriksaan tanpa perlu berpindah halaman
c) Edit — mengubah data pasien yang sudah tersimpan
d) Hapus — menghapus data pasien dari sistem
Jika belum ada pasien yang terdaftar, sistem akan menampilkan keterangan bahwa data masih kosong.
4) Halaman Antrian Pendaftaran
Halaman antrian pendaftaran menampilkan daftar semua pasien yang telah mendaftar untuk berobat ke poliklinik. Setiap baris data memuat informasi tanggal pendaftaran, nomor pendaftaran, nomor antrian, nama pasien, poli yang dituju, nama dokter yang bertugas, serta status antrian saat ini.
Status antrian terbagi menjadi empat kondisi, yaitu:
a) Menunggu Panggilan — pasien sudah mendaftar dan sedang menunggu giliran
b) Sedang Periksa — pasien sedang dalam proses pemeriksaan oleh dokter
c) Selesai — pasien sudah selesai menjalani pemeriksaan
d) Batal — pendaftaran telah dibatalkan
Perlu diketahui bahwa hanya pengguna dengan peran admin atau perawat yang dapat menambahkan, mengubah, atau menghapus data pendaftaran. Semua pengguna dapat melihat detail dari masing-masing data pendaftaran.
5) Halaman Antrian Pemeriksaan (Diagnosa)
Halaman antrian pemeriksaan khusus digunakan oleh dokter untuk melihat daftar pasien yang perlu diperiksa. Informasi yang ditampilkan meliputi tanggal dan waktu masuk pasien, nomor registrasi, nama pasien, poliklinik tujuan, nama dokter jaga, keluhan awal yang disampaikan pasien, serta status pemeriksaan saat ini.Pada halaman ini, dokter dapat melakukan dua tindakan utama, yaitu:
a) Proses Periksa — tombol ini muncul jika pasien masih berstatus menunggu atau sedang diperiksa. Dengan menekan tombol ini, dokter akan diarahkan ke halaman pengisian hasil pemeriksaan untuk mencatat diagnosa dan resep obat
b) Lihat Hasil — tombol ini muncul jika pemeriksaan sudah selesai, sehingga dokter dapat melihat kembali hasil diagnosa yang telah diinput sebelumnya. Tersedia pula tombol Batal untuk membatalkan diagnosa jika terjadi kesalahan, dan sistem akan secara otomatis mengembalikan stok obat yang sudah digunakan ke jumlah semula.
6) Halaman Data Obat
Halaman data obat digunakan untuk mengelola daftar seluruh obat dan barang farmasi yang tersedia di poliklinik. Setiap obat ditampilkan dengan informasi kode obat, nama obat, satuan (misalnya tablet atau botol), jumlah stok yang tersedia saat ini, batas stok minimal, serta status kondisi stok.
Status stok obat terbagi menjadi tiga kondisi, yaitu:
a) Aman — stok obat masih berada di atas batas minimal yang ditentukan
b) Kritis / Hampir Habis — stok obat sudah menyentuh atau berada di bawah batas minimal
c) Habis — stok obat sudah mencapai angka nol
Pengguna dapat menambahkan obat baru, mengubah data obat yang sudah ada, serta menghapus data obat. Terdapat peringatan saat hendak menghapus obat, karena jika obat tersebut pernah digunakan dalam transaksi sebelumnya, sebaiknya tidak dihapus agar riwayat penggunaan tetap tersimpan dengan baik.
7) Halaman Transaksi Stok Obat
Halaman ini mencatat semua pergerakan stok obat yang terjadi di poliklinik, baik obat yang masuk (penambahan stok dari pengadaan) maupun obat yang keluar (penggunaan). Setiap catatan transaksi menampilkan waktu transaksi, nama obat, jenis transaksi, jumlah, nama pengguna yang mencatat, serta keterangan tambahan jika ada.Apabila terdapat obat yang stoknya sudah kritis, sistem akan menampilkan pesan peringatan di bagian atas halaman disertai tautan langsung untuk mengecek data obat.
Pengguna dapat menambahkan transaksi baru untuk mencatat obat yang baru diterima atau baru dikeluarkan. Jika terjadi kesalahan pencatatan, setiap transaksi dapat dibatalkan dan sistem akan secara otomatis menyesuaikan kembali jumlah stok obat ke kondisi sebelum transaksi tersebut dilakukan.
8) Halaman Data Dokter
Halaman data dokter digunakan untuk mengelola data seluruh dokter yang bertugas di poliklinik. Informasi yang ditampilkan meliputi nama dokter, poliklinik tempat dokter bertugas, spesialisasi, nomor HP, jadwal praktek, serta nama akun yang digunakan dokter untuk masuk ke dalam sistem.Pengguna dapat menambahkan dokter baru, mengubah data dokter yang sudah ada, atau menghapus data dokter dari sistem. Perlu diperhatikan bahwa jika data dokter dihapus, maka akun login milik dokter tersebut juga akan ikut terhapus secara permanen dari sistem.
9) Halaman Data Perawat
Halaman data perawat digunakan untuk mengelola data seluruh perawat yang bertugas di poliklinik. Informasi yang ditampilkan meliputi nama perawat, nomor HP, serta nama akun yang digunakan perawat untuk masuk ke dalam sistem.Pengguna dapat menambahkan perawat baru, mengubah data perawat yang sudah ada, atau menghapus data perawat. Sama seperti data dokter, jika data perawat dihapus maka akun login milik perawat tersebut juga akan ikut terhapus secara permanen dari sistem.
10) Halaman Data Poliklinik
Halaman data poliklinik digunakan untuk mengelola daftar poli atau klinik yang tersedia dalam sistem. Setiap baris data menampilkan nama poliklinik beserta keterangan singkat mengenai poli tersebut.Pengguna dapat menambahkan poli baru, mengubah nama atau keterangan poli yang sudah ada, serta menghapus poli yang tidak lagi digunakan. Perlu diperhatikan bahwa jika suatu poli dihapus, maka semua data dokter dan data pendaftaran pasien yang berkaitan dengan poli tersebut akan ikut terhapus dari sistem.
11) Halaman Laporan
Halaman laporan merupakan pusat laporan yang menyediakan tiga jenis laporan utama untuk keperluan pengelolaan dan pemantauan poliklinik, yaitu:
a) Laporan Kunjungan Pasien — menampilkan rekap jumlah pasien dan antrian dari seluruh poli dalam periode waktu tertentu
b) Laporan Diagnosa Penyakit — menampilkan data penyakit yang paling banyak didiagnosa serta tren penyakit yang tercatat dalam kurun waktu tertentu
c) Laporan Penggunaan Obat — menampilkan data pergerakan obat masuk dan keluar, termasuk obat yang diresepkan oleh dokter kepada pasien
Setiap laporan dapat dibuka dengan menekan tombol Buka Laporan yang tersedia pada masing-masing kartu laporan.

Pembuatan Nomor Antrian Otomatis (PendaftaranController.php)
Kode ini berfungsi untuk membuat nomor antrian harian secara otomatis dan menghasilkan nomor pendaftaran unik dengan format REG-YYYYMMDD-XXX
<?php
namespace App\Http\Controllers;
use Illuminate\Http\Request;
use App\Models\Pendaftaran;
use App\Models\Pasien;
use App\Models\Poli;
use App\Models\Dokter;
use App\Models\Perawat;
use Carbon\Carbon;
use Illuminate\Support\Facades\Auth;
class PendaftaranController extends Controller
{
    publicfunction index()
    {
        $pendaftarans = Pendaftaran::with(['pasien', 'poli', 'dokter'])
                                   ->orderBy('created_at', 'desc')
                                   ->paginate(10);
        return view('pendaftaran.index', compact('pendaftarans'));
    }
    publicfunction create()
    {
        $pasiens = Pasien::all();
        $polis = Poli::all();
        $dokters = Dokter::with('user')->get();
        return view('pendaftaran.create', compact('pasiens', 'polis', 'dokters'));
    }
    publicfunction store(Request $request)
    {
        $request->validate([
            'id_pasien' => 'required|exists:pasiens,id_pasien',
            'id_poli' => 'required|exists:polis,id_poli',
            'id_dokter' => 'required|exists:dokters,id_dokter',
            'keluhan' => 'required|string',
        ]);
        $today = Carbon::today();
        // Cari perawat yang sedang login (jika role perawat)
        $id_perawat = null;
        if (Auth::user()->role == 'perawat') {
            $perawat = Perawat::where('id_user', Auth::id())->first();
            $id_perawat = $perawat ? $perawat->id_perawat : null;
        }
        // Generate Nomor Antrian per hari
        $lastAntrian = Pendaftaran::whereDate('tanggal_daftar', $today)->max('no_antrian');
        $no_antrian = $lastAntrian ? $lastAntrian + 1 : 1;
        // Generate Nomor Pendaftaran
        $nomor_pendaftaran = 'REG-' . date('Ymd') . '-' . str_pad($no_antrian, 3, '0', STR_PAD_LEFT);
        Pendaftaran::create([
            'nomor_pendaftaran' => $nomor_pendaftaran,
            'tanggal_daftar' => now(),
            'keluhan' => $request->keluhan,
            'no_antrian' => $no_antrian,
            'suhu_tubuh' => $request->suhu_tubuh,
            'berat_badan' => $request->berat_badan,
            'tinggi_badan' => $request->tinggi_badan,
            'status_pendaftaran' => 'baru',
            'id_pasien' => $request->id_pasien,
            'id_poli' => $request->id_poli,
            'id_dokter' => $request->id_dokter,
            'id_perawat' => $id_perawat,
            'id_user' => Auth::id()
        ]);
        return redirect()->route('pendaftaran.index')->with('success', 'Pendaftaran antrian berhasil dibuat.');
    }
    publicfunction show(string $id)
    {
        $pendaftaran = Pendaftaran::with(['pasien', 'poli', 'dokter', 'perawat'])->findOrFail($id);
        return view('pendaftaran.show', compact('pendaftaran'));
    }
    publicfunction edit(string $id)
    {
        $pendaftaran = Pendaftaran::findOrFail($id);
        $pasiens = Pasien::all();
        $polis = Poli::all();
        $dokters = Dokter::with('user')->get();
        return view('pendaftaran.edit', compact('pendaftaran', 'pasiens', 'polis', 'dokters'));
    }
    publicfunction update(Request $request, string $id)
    {
        $request->validate([
            'status_pendaftaran' => 'required|in:baru,diproses,selesai,batal',
        ]);
        $pendaftaran = Pendaftaran::findOrFail($id);
        $pendaftaran->update([
            'suhu_tubuh' => $request->suhu_tubuh,
            'berat_badan' => $request->berat_badan,
            'tinggi_badan' => $request->tinggi_badan,
            'status_pendaftaran' => $request->status_pendaftaran,
        ]);
        return redirect()->route('pendaftaran.index')->with('success', 'Data Pendaftaran berhasil di-update.');
    }
    publicfunction destroy(string $id)
    {
        $pendaftaran = Pendaftaran::findOrFail($id);
        $pendaftaran->delete();
        return redirect()->route('pendaftaran.index')->with('success', 'Data pendaftaran dihapus.');
    }
}
